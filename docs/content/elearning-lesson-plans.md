# eラーニング教材の企画（10本）

版: 2026-09-27 作成。
題材と順位は [題材選定 2026](topic-selection-2026.md)（以下「選定書」）に従い、出典の ID（S1 など）も選定書の第6章を指す。
教材は、汎用の図解本 skill（zukai-book）とプロジェクト専用 skill（`.claude/skills/tet2-security-zukai/`）で作る。
1本の原稿から、A5 判の図解 PDF と、情報量を絞った PowerPoint（1見開き1枚）の2形式を出力する。

## 1. 共通の方針

- **構成**：「知る、見抜く、動く」の3章で組む（skill の `references/structure-patterns.md`）。
  従業員向けは9見開き前後（20〜25分）、管理者向けは12〜14見開き（35〜45分）とする。
- **行動に紙面を使う**：章3（動く）に見開きの3分の1以上を当て、各見開きのまとめの1文を「明日から取る行動」で書く。
- **画像**：人物の場面は Codex の画像生成、画面の模式図は SVG で作る。
  流れ、対比、統計は画像にせず図解の部品で作る（skill の `references/image-types.md`）。
- **確認テスト**：教材ごとに5問を、アウェアネス小問と同じ書き方（`.claude/skills/tet2-awareness-quiz/`）で作る。
  正答率の目標は 60〜85% とする。
- **出典**：統計と制度の記述には出典を残し、選定書の第7章の未確認事項は、資料で確かめるまで書かない。

## 3. 各教材の企画

### 3.1 気づいたら、すぐ報告する：インシデントの発見と初動

- **対象者と所要時間**：全従業員、20〜25分。
- **狙い**：「おかしい」と感じた時点で、自分で判断せずに決められた窓口へ報告し、端末の電源を切らずにネットワークから切り離す行動を身につける。
- **構成**：
  - 知る：インシデントとは何か（平常と被害後の対比）、報告が遅れると何が起きるか（被害の広がり）、一般化した事例で初動の差を追う。
  - 見抜く：報告すべき兆候（不審なメールを開いた、偽の画面に入力した、画面や動作の異常）、兆候を見た場面の演習。
  - 動く：してはいけないこととすること（電源を切る、隠す、自分で直す、の対比）、報告の流れと伝える内容（いつ、どの端末で、何をしたか）、まとめと明日からの行動。
- **主な画像**：人物の場面（異変に気づく、窓口へ連絡する）、画面の模式図（異常な警告、報告フォーム）。
- **確認テストが問う行動**：報告の時機、報告先、伝える内容、端末の扱い、報告をためらう心理への対処。
- **出典**：S2、S4、S6（報告様式の一元化）、S7（SCS 評価制度の構築方針）。

### 3.2 その入力、本物の画面ですか：フィッシングと多要素認証の突破

- **対象者と所要時間**：全従業員、20分。
- **狙い**：メール、SMS、QR コード、電話で誘導された画面では入力せず、公式アプリやブックマークから開き直す行動を身につける。
- **構成**：
  - 知る：フィッシングの量と誘導の経路の広がり、多要素認証を突破する手口（中継型の偽サイト、承認通知の連打）。
  - 見抜く：誘導の入口ごとの見分け方（メール、SMS、QR コード、電話）、偽のログイン画面の演習。
  - 動く：開き直す手順、承認通知と確認コードの扱い、入力してしまった後の報告。
- **主な画像**：画面の模式図（SMS、偽のログイン画面、掲示された QR コード）、人物の場面（電話で確認コードを聞かれる）。
- **確認テストが問う行動**：開き直しの手順、QR コードの扱い、承認通知の拒否と報告、確認コードを伝えない、入力後の初動。
- **出典**：S2、S3、S9、S10、S11。
- **tet2 との連動**：訓練メールのクリック後の種明かしから、この教材へ案内する。

### 3.3 ランサムウェアに備える：組織の初動と平時の備え

- **対象者と所要時間**：部門長、情報システム担当、総務と法務の責任者、35〜45分。
- **狙い**：侵入の経路、初動の体制、バックアップと復旧の確認、社外への報告の流れを、自組織で決めて点検できるようにする。
- **構成**：
  - 知る：被害の実態（規模、業種、復旧の期間と費用）、侵入の経路、取引先や顧客への広がり。
  - 見抜く：兆候と、侵入を早く見つける仕組み（技術、運用、人の3つ）。
  - 動く：初動の体制（誰が、いつ、何を決めるか）、切り離しと証拠の保全、バックアップの保管と復元の確認、報告の手続き（警察、所管官庁、個人情報保護委員会、取引先）、平時の点検表。
- **主な画像**：人物の場面（対策会議、現場からの報告を受ける）、模式図（ネットワークの分離、バックアップの世代）。
- **確認テストが問う行動**：外部公開機器の修正、バックアップの切り離し、初動の決定者、報告先、復元の定期確認。
- **出典**：S1、S3、S6。

### 3.4 振り込む前に、別の経路で確かめる：ビジネスメール詐欺となりすまし

- **対象者と所要時間**：全従業員（経理、財務、購買と承認者に重点）、20分。
  経理向けの短い版（10分）を別に出力する。
- **狙い**：送金や口座変更の依頼を、メール以外の既知の経路で確かめ、1人で送金を完結させない行動を身につける。
- **構成**：
  - 知る：取引先や経営者を装う手口、声や映像の偽装（ディープフェイク）の広がり。
  - 見抜く：依頼の特徴（急がせる、秘密にさせる、経路を変えさせる）、演習。
  - 動く：確認の手順、承認の流れ、報告。
    管理者向けの見開きで承認規程に書く事項を示す。
- **主な画像**：人物の場面（請求書とメールを見比べる、上司を名乗る電話）、画面の模式図（チャットの招待）。
- **確認テストが問う行動**：署名の電話番号を使わない、返信で確かめない、チャットのグループ作成依頼への対応、声だけで判断しない、承認の分離。
- **出典**：S1、S2、S13、S14。

### 3.5 パスワードと多要素認証の正しい使い方

- **対象者と所要時間**：全従業員、10分（小問が中心）。
- **狙い**：使い回しをやめ、多要素認証を有効にし、身に覚えのない通知を報告する。
- **構成**：知る（使い回しで起きること）、動く（会社が認めた管理方法、多要素認証の設定、通知を受けた時）の2章6見開き。
- **主な画像**：人物の場面（承認通知を受け取る）、模式図（パスキーの流れ）。
- **確認テストが問う行動**：使い回し、承認通知の拒否、確認コードの扱い、パスキーの利点、通知後の報告。
- **出典**：S2、S12。

### 3.6 送る前、渡す前の確認：個人情報と機密情報の取扱い

- **対象者と所要時間**：全従業員 20分、管理者向けの章を加えた版 30分。
- **狙い**：誤送付と誤交付を送信前の確認で防ぎ、機密区分に応じて持ち出しと保存先を判断する。
- **構成**：
  - 知る：漏えい等報告の原因の内訳（誤交付と誤送付が多い）。
  - 見抜く：誤送付が起きる場面（宛先の自動補完、添付の取り違え）。
  - 動く：送信前の確認手順、機密区分と持ち出し、起きた時の報告。
    管理者向けに、個人情報保護委員会への報告と本人への通知が必要になる場合と判断の窓口。
- **主な画像**：人物の場面（送信前に宛先を確かめる、窓口で書類を渡す）、模式図（メール作成画面の宛先欄）。
- **確認テストが問う行動**：宛先の確認、添付の確認、私物媒体、持ち出しの判断、誤送付後の報告。
- **出典**：S4、S5。
  令和8年改正の施行内容が確定した時点で管理者向けの章を更新する。

### 3.7 生成AIを業務で使うときの決まりごと

- **対象者と所要時間**：全従業員 20分、管理者向けの章を加えた版 30分。
- **狙い**：許可されたサービスだけを使い、入力する情報を選び、出力を一次資料で確かめる。
- **構成**：
  - 知る：業務で使う場面と、情報が外に出る経路。
  - 見抜く：入力してはいけない情報、出力の誤り（数値、固有名、引用）、声や映像の偽装。
  - 動く：許可されたサービス、入力前の確認、出力の検証、偽装への対処。
    管理者向けに規程で決める事項の例。
- **主な画像**：人物の場面（入力する前に手を止める、出力を資料と照合する）、模式図（チャット画面）。
- **確認テストが問う行動**：個人アカウントに業務データを入れない、出力の検証、許可されていないサービス、声の依頼への確認、規程の確認。
- **出典**：S1、S2、S3。

### 3.8 委託先と取引先のセキュリティをどう確かめるか

- **対象者と所要時間**：管理者（購買、情報システム、法務）、35分。
- **狙い**：取引先から求められうる評価制度を把握し、委託先との役割、連絡方法、確認の運用を決める。
- **構成**：
  - 知る：取引先を経由した侵入の実態、SCS 評価制度の概要と開始時期。
  - 見抜く：委託先の点検項目。
  - 動く：契約と覚書に書く事項、インシデント時の連絡、請求と口座変更の確認の運用。
- **主な画像**：人物の場面（委託先との打合せ）、模式図（取引の連なりと侵入の経路）。
- **確認テストが問う行動**：制度の段階の把握、契約の記載事項、連絡の経路、口座変更の確認、自社の点検。
- **出典**：S1、S2、S4、S7、S8。
  要求事項の項番は、資料で確かめてから書く。

### 3.9 偽の警告画面が出たら：サポート詐欺への対処

- **対象者と所要時間**：全従業員、10分（小問と1枚の図解が中心）。
- **狙い**：警告の電話番号にかけず、ブラウザを閉じ、電話や遠隔操作をしてしまった場合も隠さず報告する。
- **構成**：見抜く（偽の警告の特徴）、動く（閉じる手順、閉じられない時、してしまった後の報告）の2章5見開き。
- **主な画像**：模式図（偽の警告画面、文字は線で表す）、人物の場面（警告音に驚く）。
- **確認テストが問う行動**：電話しない、閉じる手順、遠隔操作ソフト、してしまった後の報告、業務端末と私物の違い。
- **出典**：S1、S3、S12、S13。

### 3.10 退職と異動のときの情報管理：内部不正を防ぐ仕組み

- **対象者と所要時間**：管理者（人事、情報システム、部門長）、30分。
- **狙い**：不要な ID と権限の削除、退職時の回収、アクセス記録と周知による抑止を仕組みにする。
- **構成**：
  - 知る：内部不正の類型（意図的なものと過失）と、起きる条件。
  - 見抜く：兆候と記録の使い方。
  - 動く：ID の棚卸し、退職時の点検表、記録と周知。
- **主な画像**：人物の場面（退職の手続き）、模式図（権限の棚卸し）。
- **確認テストが問う行動**：ID の削除の時機、回収の項目、記録の周知、私物媒体、持ち出しの禁止。
- **出典**：S1、S2、S4。

## 4. 制作の順序

完成品の2本（3.1 と 3.3）で品質の確認を受けた後、残りを次の順に作る。

1. 3.2 と 3.4：訓練メールの結果と連動させやすく、顧客への説明がしやすい。
2. 3.6 と 3.7：両方の対象者に要る題材で、規程の更新にも使える。
3. 3.8 と 3.10：管理者向けで、取引先からの要求への備えになる。
4. 3.5 と 3.9：小問を中心にし、短い教材を添える。
