# 次の教育コンテンツの企画案 2026

版: 2026-09-27 作成（企画の段階。教材と設問の原稿はまだない）。
既存の企画は [eラーニング教材の企画（10本）](elearning-lesson-plans.md)（以下「既存企画」）、題材の選び方と出典は [題材選定 2026](topic-selection-2026.md)（以下「選定書」）、小問は [アウェアネス小問（30問）](awareness-question-plans.md) にある。
出典の ID のうち、S で始まるものは選定書の第6章、N で始まるものはこの文書の第7章を指す。

## 1. 結論

既存の10本と重ならない教材を10本企画した（企画11〜20）。
優先度は高が3本、中が5本、低が2本である。

最初に作るのは次の3本とする（理由は第6章）。

1. 企画11「入社の日に覚える5つの行動」：SCS 評価制度の★3が求める新規受入れ時の教育に直接使え、既存の10本への入口にもなる。
2. 企画12「訓練のメールで、どこで気づけたか」：tet2 の本番の訓練で、偽サイトを表示した人の58.4%が入力まで進んでおり[N14]、訓練から教育への自動連携の機能（`phishing_failure`）がすでにある。
3. 企画13「経営層が決めておくこと」：SCS 評価制度の★4が経営層の教育を求め、ランサムウェアの被害組織で BCP を策定済みだったのは約18%にとどまる[S3]。

小問は、新設カテゴリを6つ提案し（aw-mobile、aw-factory、aw-office、mg-executive、mg-incident、mg-itops）、見本を9問書いた。
出し方は、季節の手口に合わせた年間の出題計画、訓練との連動、難易度の段階、部署別の出し分けの4つを提案する。
このうち年間計画は、今の機能では12回の配信を作り、各月の当日に手で開始すれば実施できる。配信に予約の日時は保存できるが、その日時に自動で開始する処理はない（2026-09-28 にコードで確認）。
繰り返しの配信規則、出題済みの設問の除外、役職区分での対象指定、報告した人への出題は、機能の追加が要る。

## 2. 題材の選び方

選定書の4軸（被害の大きさ、発生頻度、従業員の行動で防げる度合い、外部から求められる度合い）をそのまま使った。
既存の10本は「手口」を切り口に選んでいるため、今回は次の2つの切り口で、手口の軸では拾えなかった題材を探した。

- **対象者の切り口**：新入社員、経営層、開発者と IT 担当、工場の現場のように、既存の教材では対象から外れているか、一般の従業員とまとめて扱われている層。
- **場面の切り口**：スマートフォン、社外と出張、執務室と来訪者、インシデントの演習のように、既存の教材の中では節や小問の1問として扱っただけの場面。

tet2 の機能と連動できるか（訓練の結果から教育を出せるか）を、優先度の判断に加えた。
tet2 の強みは訓練と教育を同じ場所で扱えることで、その連動は他の教材の購入理由になりやすいためである。

一次情報で数値を確かめられなかった題材（物理的な情報管理、SNS）は、根拠に数値を書かず、優先度を下げた。
医療や小売の業種別の版、ディープフェイクの単独の教材は、今回は企画しない（第5章の末尾）。

### 3.2 企画11 入社の日に覚える5つの行動：はじめてのセキュリティ

- **対象者と所要時間**：新入社員、中途入社、派遣社員、受入出向者。20分。
- **狙い**：入社の初日から、次の5つの行動を取れるようにする。
  1. おかしいと感じたら、すぐ窓口へ報告する。
  2. パスワードを使い回さず、多要素認証の通知やコードを他人に渡さない。
  3. メールや SMS のリンクから ID とパスワードを入力しない。
  4. 業務の情報を、会社が認めた場所と方法でだけ扱う（私用のメール、私用のクラウド、私用の AI に入れない）。
  5. 社内の規程と窓口の場所を知っている。
- **章立ての骨子**：
  - 知る：会社の情報と自分の ID が狙われる理由、入社直後の人が狙われやすい場面（新しいアカウント、慣れない社内の通知）。
  - 見抜く：5つの行動ごとに1場面ずつ（報告、承認通知、偽のログイン画面、私用サービス、規程の場所）。
  - 動く：窓口の連絡先を書き込む欄、最初の1週間で確かめること（多要素認証の設定、規程の置き場所）、既存の10本のどれを次に読むかの案内。
- **根拠**：
  - SCS 評価制度の★3の要求事項は、役員、従業員、派遣社員、受入出向者に、新規受入れ時と年1回以上、インシデント発生時の対応を e ラーニングか集合教育で教育し、記録することを求めている[S7a]。
  - 経済産業省が中小企業126社に行った、インターネットから見える資産の診断（IPA の事例集に収録）では、ログインに使う ID とパスワードの流出が101社で見つかった[N2]。入社時に使い回しをやめる習慣を作る理由になる。
  - 2025年のフィッシング報告件数は2,454,297件である[S3]。
- **既存の10本との違い**：既存の10本は題材ごとに深く扱う。企画11は5つの行動を1本に絞った入口で、各行動の詳しい説明は既存の教材（既存企画の3.1、3.2、3.5、3.6、3.7）へ案内する。入社の手続きの一部として配ることを想定し、会社ごとの窓口と規程を書き込める欄を設ける。
- **小問のカテゴリ**：既存の aw-report、aw-auth、aw-phishing、aw-data、aw-genai から1問ずつ出す。新設はしない（カテゴリは題材で分け、対象者は配信の対象で分けるため）。
- **優先度**：高。外部からの要求（新規受入れ時の教育）が明確で、既存の10本の完成品を組み替えて作れるため、制作の費用が小さい。

### 3.3 企画12 訓練のメールで、どこで気づけたか：開いた人への振り返り

- **対象者と所要時間**：標的型メール訓練でリンクを開いた人、偽のログイン画面に入力した人。10分。
- **狙い**：自分が見落とした手掛かりを、訓練とは別の見本のメールで確かめ、次に同じ種類のメールを受けた時に、開く前に手を止めて報告できるようにする。
- **章立ての骨子**：
  - 知る：訓練の目的（責めるためではなく、本物の攻撃の前に練習するため）、開いた後に入力まで進む人が多いこと。
  - 見抜く：見本のメールで、手掛かりを順に確かめる（差出人の実際のアドレス、急がせる文面、リンク先の表示、ログイン画面のアドレス）。
  - 動く：入力してしまった時の初動（パスワードの変更と報告）、次に不審なメールを受けた時の報告の方法。
- **根拠**：
  - tet2 の本番の訓練（2026年8月、ある顧客の1回、対象1,876名）では、偽サイトの表示が185名（9.9%）、偽のログイン画面への入力が108名（対象の5.8%）で、表示した人の58.4%が入力まで進んだ[N14]。開いた人への教育は、入力を止めるところに重点を置く必要がある。
  - 実在するサービスのドメインを差出人に使った「なりすまし」フィッシングメールが、2026年8月に調査用アドレスに届いた分の約32.3%を占めた[S10]。差出人の表示だけでは見分けられない場合があることを教材に書く根拠になる。
  - 「機密情報を狙った標的型攻撃」は、情報セキュリティ10大脅威 2026 組織編の5位である[S1]。
- **既存の10本との違い**：既存企画の3.2（フィッシングと多要素認証の突破）は全従業員向けの基礎である。企画12は、訓練で開いた人だけに、開いた直後に出す短い振り返りで、3.2 を読んだ前提で手掛かりの確かめ方に絞る。
  訓練の測定を壊さないため、実際の訓練メールの件名、差出人、テンプレートは教材に載せず、別に作った見本のメールで説明する（tet2 の規則）。
- **小問のカテゴリ**：既存の aw-mail、aw-phishing、aw-report。
- **優先度**：高。tet2 の自動連携（`triggered_by = phishing_failure`）で、開いた人に自動で配信できる。訓練の結果と教育の受講を同じ画面で説明でき、tet2 を選ぶ理由を顧客に示しやすい。

### 3.4 企画13 経営層が決めておくこと：サイバー攻撃を経営のリスクとして扱う

- **対象者と所要時間**：役員、経営層。30分。取締役会の前などに使う短い版（15分）を別に出力する。
- **狙い**：サイバー攻撃を経営のリスクとして扱い、次の事項を経営者として決め、担当に指示できるようにする。
  1. 対策の方針と、責任者、予算、人材。
  2. インシデントが起きた時に、誰が何を決めるか（業務の停止、社外への公表、取引先と当局への連絡）。
  3. 事業を続け、復旧する計画（サイバー攻撃を想定した BCP）。
  4. 委託先と取引先を含めた対策の状況の把握。
- **章立ての骨子**：
  - 知る：被害が経営に与える影響（復旧の費用と期間、受注と出荷の停止、個人情報の漏えい）、取引先から求められる評価制度。
  - 見抜く：自社の状況を確かめる問い（経営ガイドラインの重要10項目に沿った10の問い）。
  - 動く：経営者が平時に決めること、インシデントの時に経営者が決めること、担当への指示の例。
  - 従業員向けのスライド版：「会社が決めている方針と、従業員に求めること」（報告の窓口、報告した人を責めない方針）に絞る。
- **根拠**：
  - サイバーセキュリティ経営ガイドライン Ver3.0 は、経営者が認識すべき3原則と、経営者が担当に指示すべき重要10項目（体制の構築、資源の確保、緊急対応体制、事業継続と復旧体制、サプライチェーン全体の対策など）を示している[S8][N1]。
  - SCS 評価制度の★4の要求事項は、経営層が情報セキュリティ上の役割と責任を理解する機会を設けることを求めている[S7a]。
  - 警察庁のアンケートでは、2025年にランサムウェアの被害に遭った組織のうち、BCP を策定済みだったのは約18%で、復旧に総額1,000万円以上を要した組織は5割を超えた[S3]。
  - 2025年には、ランサムウェアの攻撃で製品の受注と出荷が止まった事例が警察庁の資料に記載されている[S3]。
- **既存の10本との違い**：既存企画の3.3（ランサムウェアに備える）は部門長と実務の責任者が初動と平時の備えを点検する教材である。企画13は、経営者が決めることと担当への指示に絞り、個々の技術対策は扱わない。既存企画の3.8（委託先）は購買と法務の実務で、企画13ではサプライチェーンを経営の責任として1見開きで扱うにとどめる。
- **小問のカテゴリ**：新設の mg-executive。
- **優先度**：高。経営層の教育は SCS 評価制度の★4で求められ、経営ガイドラインも経営者の関与を前提にしている。教育の予算を決める層に届く教材で、顧客に教育全体を採用してもらう入口にもなる。

### 3.5 企画14 その72時間、誰が何をするか：ランサムウェアを想定した机上演習

- **対象者と所要時間**：部門長、情報システム担当、総務、広報、法務、経理の責任者。教材30分と、演習60〜90分。
- **狙い**：ランサムウェアの被害を想定した場面を、時間の経過に沿って役割ごとに判断し、自社の手順と連絡先の不足を見つけて直せるようにする。
- **章立ての骨子**：
  - 知る：机上演習の進め方（進行役、参加者、記録係）、演習で確かめること（決める人、連絡先、切り離しの判断、社外への報告）。
  - 見抜く：時間の経過に沿って届く状況の付与（発見、拡大、社外からの問合せ、報道からの問合せ）と、役割ごとの判断。
  - 動く：演習の後に直すこと（連絡先の一覧、報告の様式、判断の権限）、翌年の演習の計画。
  - 本の版は、進行役の台本、状況の付与のカード、振り返りの記録表を収める。
  - 従業員向けのスライド版：「インシデントの時に、従業員が求められること」（報告、端末を触らない、社外に話さない）。
- **根拠**：
  - 警察庁は、ランサムウェアの攻撃を受けた際の対応に関する訓練を、被害の抑制に有効な管理体制の1つに挙げている[S3]。
  - 同じ資料で、被害組織のうち BCP を策定済みだったのは約18%である[S3]。
  - 経営ガイドライン Ver3.0 の重要10項目は、インシデント発生時の緊急対応体制と、事業継続と復旧体制の整備を含む[N1]。
  - ランサムウェア事案では、官公署への報告に使える共通様式が定められている[S6]。演習で、この様式を実際に埋めてみる。
- **既存の10本との違い**：既存企画の3.3は、何を備えるかを読んで学ぶ教材である。企画14は、3.3で学んだ内容を、参加者が役割を持って判断する演習の形式で確かめる。
- **小問のカテゴリ**：新設の mg-incident。
- **優先度**：中。演習は効果が大きい一方で、進行役が要り、顧客ごとの体制に合わせた調整が要る。既存企画の3.3の品質確認が済んでから、その続きとして作る。

### 3.6 企画15 鍵を置く場所、扉の閉め方：秘密情報とクラウドの設定

- **対象者と所要時間**：開発者、情報システム担当、Web サイトの担当者、委託先の管理者。35分。
- **狙い**：API キーやパスワードなどの秘密情報をソースコードや公開の場所に置かず、漏れた時にすぐ無効化し、クラウドと管理画面の公開範囲と設定を定期的に確かめられるようにする。
- **章立ての骨子**：
  - 知る：秘密情報とは何か（API キー、クラウドの認証情報、パスワード、証明書の秘密鍵）、漏れる経路（公開のリポジトリ、設定ファイル、Web サイトの公開フォルダ）。
  - 見抜く：設定の不備の典型（管理画面の公開、フォルダの一覧表示、権限の広すぎる鍵）、点検の手順。
  - 動く：漏れた時の手順（無効化、新しい鍵の発行、利用記録の確認、報告）、権限を最小にする、設定の点検表。
  - 従業員向けのスライド版：「パスワードや鍵をチャット、メール、共有フォルダに貼らない」に絞る。
- **根拠**：
  - IPA の事例集では、中小企業126社の診断で、API キーやクラウドの認証情報の流出が8社、リポジトリや設定情報の露出が13社、管理画面の公開が18社で見つかった[N2]。同じ資料は、流出した鍵をすぐに無効化して新しいものを発行し、新しい鍵には最低限の権限だけを与えることを対策に挙げている[N2]。
  - 警察庁は、攻撃者が未修正の脆弱性、漏えいした認証情報、簡易なパスワード、設定不備を悪用して組織のネットワークへ侵入すると記している[S3]。
  - 総務省は、クラウドサービスの利用者と提供者が設定の誤りを防ぐためのガイドラインを2022年10月に[N3]、その内容を分かりやすくしたガイドブックを2024年4月26日に公表した[N4]。
  - 「システムの脆弱性を悪用した攻撃」は、10大脅威 2026 組織編の4位である[S1]。
- **既存の10本との違い**：既存の10本は、技術者でない従業員と管理者を対象にしている。選定書では、クラウドの設定不備を「従業員の行動で防げる度合いが低い」として管理者向けの章に統合したが、既存企画の3.3と3.8には設定と秘密情報を扱う章がない。企画15は、設定を行う技術者を対象者として独立させる。
- **小問のカテゴリ**：新設の mg-itops。
- **優先度**：中。根拠は明確だが、対象者が限られる。IT 部門や開発部門を持つ顧客から求められた時に作る順序でよい。

### 3.7 企画16 手のひらの端末を守る：スマートフォンと QR コード

- **対象者と所要時間**：業務用スマートフォンを使う全従業員（私用の端末で業務のサービスを使うことを認めている会社では、その利用者も含む）。15分。
- **狙い**：スマートフォンで受けたメール、SMS、QR コードから開いた画面に入力せず、公式アプリとブックマークから開き直す。アプリを公式のストアからだけ入れ、端末の画面ロックと紛失時の報告を守る。
- **章立ての骨子**：
  - 知る：スマートフォンで業務を扱う場面（メール、チャット、多要素認証のアプリ、写真）と、狙われる理由。
  - 見抜く：QR コードから誘導される画面、アプリの入手を案内する SMS、アプリが求める権限。
  - 動く：開き直しの手順、アプリの入れ方、画面ロック、紛失した時の報告。
- **根拠**：
  - フィッシング対策協議会は、メールに記載した QR コードからクレジットカード会社の偽サイトへ誘導する手口を緊急情報として公表し、QR コードからログインを促すメールは不正メールの可能性が高いとしている[N7]。
  - IPA の相談窓口には、社長や役員を名乗るメールで LINE グループの作成と QR コードの返信を求める手口の相談が、約3か月で106件寄せられた[S14]。
  - 10大脅威 2026 個人編は、「不正アプリによるスマートフォン利用者への被害」と「スマホ決済の不正利用」を挙げている[S1]。
  - 一方で、フィッシング対策協議会の2026年8月の報告は、SMS から誘導されるフィッシングの報告数は少ない状態が続いているとしている[S10]。そのため、SMS だけに紙面を割かず、QR コードとアプリの扱いに重点を置く。
- **既存の10本との違い**：既存企画の3.2は、誘導の入口の1つとして QR コードを扱う。企画16は、スマートフォンという端末を切り口にし、アプリ、権限、画面ロック、紛失まで扱う。QR コードの見分け方は3.2と重なるため、1見開きにとどめる。
- **小問のカテゴリ**：新設の aw-mobile。
- **優先度**：中。行動で防げる度合いは高いが、QR コードによるフィッシングの国内の公的な統計は確かめられていない（選定書の第7章）。

### 3.8 企画17 社外で働く、出張する：持ち出し、移動、長期休暇の前後

- **対象者と所要時間**：全従業員（営業、出張の多い職種、在宅勤務の利用者に重点）。15〜20分。
- **狙い**：端末と書類を持ち出す時、移動中、宿泊先、在宅で、会社が認めた方法で接続して作業し、紛失に気づいたらすぐ報告する。長期休暇の前後に、端末の更新と検査を会社の手順で行う。
- **章立ての骨子**：
  - 知る：社外で起きること（紛失、盗み見、公衆の無線 LAN、宿泊先への置き忘れ）。
  - 見抜く：移動、カフェ、宿泊先、自宅の場面ごとの注意。
  - 動く：持ち出しの手続き、会社が認めた接続、紛失時の報告、長期休暇の前後の手順（持ち出した端末や USB メモリを社内で使う前の検査）。
- **根拠**：
  - 「リモートワーク等の環境や仕組みを狙った攻撃」は、10大脅威 2026 組織編の8位である[S1]。
  - 個人情報保護委員会への漏えい等報告のうち、報告者自身が漏えい元の事案の4.9%が紛失である[S4]。
  - IPA は、長期休暇中に持ち出していたパソコンや USB メモリを組織内で使う前に、ウイルスの検査を行うことを勧めている[N8]。
- **既存の10本との違い**：既存企画では、テレワークと持ち出しを3.5と3.6の節として扱うにとどめ、小問の aw-remote が3問あるだけである（選定書の第4章の「11位以下の扱い」）。企画17は、社外の場面を1本にまとめる。
- **小問のカテゴリ**：既存の aw-remote。
- **優先度**：中。行動で防げる度合いが高く、長期休暇の前（4月、7月、12月）に配信する時機がはっきりしている。

### 3.9 企画18 生産設備を止めないために：工場と現場のセキュリティ

- **対象者と所要時間**：製造業の現場の従業員、設備保全、生産技術。20分。工場長と生産管理の責任者向けの章を加えた版は30分。
- **狙い**：生産設備につながる端末に、許可のない USB メモリや私物の機器をつながず、保守業者の接続を決められた手順で扱い、設備の異常を報告できるようにする。
- **章立ての骨子**：
  - 知る：工場のネットワークと事務所のネットワークのつながり、攻撃で生産が止まる経路。
  - 見抜く：持ち込み機器、保守業者の遠隔接続、設備の端末でのメールや Web の利用、共有のアカウント。
  - 動く：持ち込みの手順、保守業者の作業の立会いと記録、異常を見た時の報告先。
  - 管理者向けの章：工場の資産の把握、事務所と工場のネットワークの分け方、保守の契約に書く事項。
- **根拠**：
  - 警察庁によると、2025年のランサムウェア被害の組織を業種別に見ると製造業が約4割を占める[S3]。
  - 経済産業省は、工場のセキュリティ対策の考え方と手順を示す「工場システムにおけるサイバー・フィジカル・セキュリティ対策ガイドライン」を2022年11月に公開した[N5][N6]。
  - IPA の事例集では、管理用や制御用の通信の外部公開が126社中2社で見つかった[N2]。
- **既存の10本との違い**：既存の10本は事務所の業務を前提にしており、生産設備と現場の従業員を扱う教材はない。
- **小問のカテゴリ**：新設の aw-factory。
- **優先度**：中。tet2 の想定顧客には製造業が多く、被害の業種別の統計も製造業が最多である。ただし、持ち込みや保守の手順は工場ごとに違うため、制作の前に顧客の現場の手順を聞き取る必要があり、最初の3本には入れない。

### 3.10 企画19 机の上、扉の前、受付：執務室と来訪者の情報管理

- **対象者と所要時間**：全従業員（受付、総務、来訪者の多い部署に重点）。15分。
- **狙い**：入館証を持たない人を一緒に入れず、来訪者に同行し、離席時に画面をロックし、机の上と印刷物を片付け、書類を決められた方法で廃棄する。
- **章立ての骨子**：
  - 知る：執務室から情報が出る経路（入館、のぞき見、置き忘れ、廃棄）。
  - 見抜く：後ろから続いて入ろうとする人、作業員を名乗る人、複合機に残った印刷物。
  - 動く：声のかけ方と案内先、離席時の画面ロック、印刷物と廃棄の扱い。
- **根拠**：
  - 個人情報保護委員会への漏えい等報告では、報告者自身が漏えい元の事案の原因のうち、誤交付が45.5%、紛失が4.9%である[S4]。書類を扱う場面の管理は、この2つを減らす行動に当たる。
  - 入館や来訪者に起因する被害の国内の公的な統計は確かめられなかった。
- **既存の10本との違い**：既存企画の3.6は、宛先と添付の確認で誤送付と誤交付を防ぐ教材である。企画19は、入館、来訪者、画面、机の上、廃棄という物理の場面を扱う。誤交付は3.6に任せ、企画19では扱わない。
- **小問のカテゴリ**：新設の aw-office。
- **優先度**：低。行動で防げる度合いは高いが、統計の根拠が弱く、外部からの要求も確かめられていない。

### 3.11 企画20 投稿する前に：SNS の発信と偽情報

- **対象者と所要時間**：全従業員。10〜15分。
- **狙い**：業務の情報や、社内の写真に写り込んだ情報を投稿しない。災害や事件の時に、真偽の分からない情報を広めない。会社を名乗る偽のアカウントや、会社についての誤った情報を見つけたら窓口へ知らせる。
- **章立ての骨子**：
  - 知る：投稿から情報が漏れる経路（写り込み、予定の投稿、公開範囲の誤解）、偽情報が広がる時期。
  - 見抜く：写真の写り込み、出所の分からない情報。
  - 動く：投稿前の確認、広める前の確認、会社を名乗る偽の発信を見た時の報告。
- **根拠**：
  - 10大脅威 2026 個人編は「ネット上の誹謗・中傷・デマ」を、組織編は6位に「地政学的リスクに起因するサイバー攻撃（情報戦を含む）」を挙げている[S1]。
  - IPA は2026年の夏休みの注意喚起で、戦争に関連する記念日の前後に、過去に DDoS 攻撃や情報戦が行われたことを挙げ、偽情報の流布に注意を呼びかけている[N10]。
  - 業務の情報の投稿に起因する被害の国内の公的な統計は確かめられなかった。
- **既存の10本との違い**：既存では小問の aw-remote-03 が SNS の投稿を1問扱うだけで、教材はない。
- **小問のカテゴリ**：既存の aw-remote（将来に SNS の設問が増えたら、aw-sns として分ける）。
- **優先度**：低。業務上の要求が弱く、統計も確認できない（選定書の判断と同じ）。短い教材と小問にとどめる。

## 4. アウェアネス小問の企画案

### 4.1 今のカテゴリと新設の案

今の小問のカテゴリは、従業員向けの aw が10個（aw-mail、aw-phishing、aw-auth、aw-malware、aw-bec、aw-genai、aw-data、aw-report、aw-scam、aw-remote）、管理者向けの mg が2個（mg-vendor、mg-offboarding）で、合わせて12個である。
新しい教材に合わせて、次の6個を新設する案とする。

| 記号 | 名前 | 対象 | 対応する企画 | 問う行動の例 |
|---|---|---|---|---|
| aw-mobile | スマートフォンと QR コード | 従業員 | 企画16 | QR コードから入力しない、公式のストア以外からアプリを入れない、権限の確認、画面ロック |
| aw-factory | 工場と生産設備 | 従業員（製造業） | 企画18 | 持ち込み機器、保守業者の接続、設備の端末での私的な利用、異常の報告 |
| aw-office | 執務室と来訪者 | 従業員 | 企画19 | 共連れ、来訪者の同行、離席時の画面ロック、廃棄 |
| mg-executive | 経営層の役割 | 経営層 | 企画13 | 平時に決めること、インシデント時の判断者、公表の判断、委託先を含めた把握 |
| mg-incident | インシデント対応の体制と演習 | 管理者 | 企画14 | 連絡先の保管、判断の権限、報告の様式、演習の振り返り |
| mg-itops | 秘密情報とクラウドの設定 | 開発者、IT 担当 | 企画15 | 漏れた鍵の無効化、最小の権限、公開範囲の点検、秘密情報の受け渡し |

既存のカテゴリにも、季節の手口に合わせたテーマを足す（4.3 の年間計画で使う）。

- **aw-mail**：長期休暇の明けの端末とメール、年末年始の配送や請求を装うメール。
- **aw-bec**：決算期の請求書と口座変更、年末から年度末の社長なりすまし。
- **aw-scam**：国税庁や税務署を名乗る SMS とメール（確定申告の時期）、銀行を名乗る電話（ボイスフィッシング）。
- **aw-remote**：出張と長期休暇の持ち出し。

### 4.2 設問の見本

書き方は既存の小問（`.claude/skills/tet2-awareness-quiz/`）に合わせ、選択肢ごとの解説を付けた。
tet2 は設問に選択肢ごとの解説（`option_explanations`）と場面の画像（`image_name`）を持てるので、見本の解説はそのまま取り込める形で書いた。
正解の位置は、9問で1から4に散らした。

#### aw-mobile（スマートフォンと QR コード）

**aw-mobile-01**（場面、難易度 2、狙う正答率 70%）

取引先を名乗るメールに「請求書の確認はこちらから」と QR コードの画像が貼られていた。業務用スマートフォンで読み取ると、会社のメールサービスのログイン画面が開いた。どうするか。

1. 画面の見た目がいつもと同じなら、ID とパスワードを入力する
2. 入力せずに閉じ、メールを窓口に報告する（正解）
3. スマートフォンではなくパソコンで QR コードを読み取り直す
4. 取引先にメールで返信し、本物かどうかを尋ねる

選択肢ごとの解説：

1. 偽のログイン画面は本物と見分けがつかないように作られる。見た目は確かめる根拠にならない。
2. QR コードから開いた画面では入力しない。ログインが必要なら、ブックマークや公式アプリから開き直す。
3. 読み取る端末を変えても、開く先は同じ偽の画面である。
4. 返信は攻撃者に届くおそれがある。確かめるなら、以前から知っている連絡先を使う。

ポイント：QR コードから開いたログイン画面には入力せず、普段の入口から開き直し、メールを報告する。
出典：N7。

**aw-mobile-02**（最も適切、難易度 1、狙う正答率 82%）

業務用スマートフォンに、宅配業者を名乗る SMS で「不在のため再配達はアプリから。こちらから入手して」とリンクが届いた。最も適切な対応はどれか。

1. 再配達を急ぐため、リンクからアプリを入れる
2. アプリを入れた後、不要なら削除すればよい
3. リンクを開かず、必要なら宅配業者の公式サイトで確かめる（正解）
4. 同僚に同じ SMS が届いていないかを確かめてから入れる

選択肢ごとの解説：

1. SMS のリンクから入れるアプリは、不正なアプリのおそれがある。入れると、端末の情報を抜き取られるおそれがある。
2. 削除しても、入れていた間に抜き取られた情報や、許可した権限による被害は戻らない。
3. リンクは開かない。業務用の端末には、会社が認めた公式のストアからだけアプリを入れる。
4. 同僚に同じ SMS が届いていても、本物である証拠にはならない。

ポイント：SMS のリンクからアプリを入れず、公式のサイトやアプリで確かめる。
出典：S1（個人編の「不正アプリによるスマートフォン利用者への被害」）。

#### aw-factory（工場と生産設備）

**aw-factory-01**（場面、難易度 2、狙う正答率 70%）

設備メーカーの保守担当者が、持参した USB メモリで生産設備の制御用のパソコンにプログラムを入れたいと言う。今日中に直したいと急いでいる。どうするか。

1. 設備メーカーの担当者なので、そのまま作業してもらう
2. 急ぎなので作業してもらい、終わった後で上司に伝える
3. 自分の業務用パソコンで USB メモリの中身を開き、確かめる
4. 工場で決めた持ち込みの手順に沿って、設備の担当者の許可を取る（正解）

選択肢ごとの解説：

1. 業者の機器や媒体が、業者も知らないうちに感染していることがある。相手が誰でも手順を省かない。
2. 作業の後で伝えても、感染した媒体をつないだ後では取り返せない。
3. 事務所の端末につなぐと、そちらが感染するおそれがある。検査は工場で決めた方法で行う。
4. 持ち込み機器は、工場で決めた手順（検査、許可、記録）に沿って扱う。

ポイント：生産設備につなぐ機器と媒体は、相手が誰でも、工場の持ち込みの手順に沿って扱う。
出典：N5（持ち込みの手順の考え方）。社内の手順があればそれに従う、を解説の前に置く。

#### aw-office（執務室と来訪者）

**aw-office-01**（場面、難易度 1、狙う正答率 84%）

入館証をかざして執務室の扉を開けると、段ボールを抱えた見知らぬ人が「手がふさがっているので」と後ろから一緒に入ろうとした。どうするか。

1. 荷物を持っているので、扉を押さえて入れてあげる
2. 作業着を着ていれば業者なので、そのまま入れる
3. 入館証を確かめ、持っていなければ受付に案内する（正解）
4. 入れた後で、総務に「知らない人が入った」と伝える

選択肢ごとの解説：

1. 手がふさがった相手を助けたい気持ちにつけ込まれることがある。入館証を確かめずに入れると、入館の管理が働かなくなる。
2. 作業着は誰でも用意できる。服装は入館を許す根拠にならない。
3. 1人ずつ入館証で入るのが原則で、持っていない人は受付か担当者へ案内する。
4. 入れた後では、どこへ行ったかを追えないことがある。入れる前に止める。

ポイント：入館証を持たない人を一緒に入れず、受付か担当者に案内する。
出典：なし（事実を書かない設問）。

#### mg-executive（経営層の役割）

**mg-executive-01**（最も適切、難易度 2、狙う正答率 70%）

ランサムウェアの被害に備えて、経営者が平時に行っておくこととして最も適切なものはどれか。

1. 被害が起きた時に誰が何を決めるかを定め、訓練で確かめる（正解）
2. 技術の詳細は分からないので、すべて情報システム担当に任せる
3. ウイルス対策ソフトを入れているので、特に決めることはない
4. 被害が起きてから、社外の専門家に体制を作ってもらう

選択肢ごとの解説：

1. 業務の停止、公表、取引先と当局への連絡は経営の判断である。誰が決めるかを平時に定め、演習で確かめておく。
2. 技術対策は担当に任せられるが、方針、資源、事業の停止の判断は経営者にしかできない。
3. ウイルス対策ソフトだけでは、外部に公開された機器からの侵入などは防げない。
4. 被害が起きてから体制を作ると、判断が遅れて被害が広がる。専門家への連絡先も平時に決めておく。

ポイント：インシデントの時に誰が何を決めるかを平時に定め、演習で確かめる。
出典：N1（重要10項目の緊急対応体制）、S3（BCP の策定状況、訓練の有効性）。

#### mg-incident（インシデント対応の体制と演習）

**mg-incident-01**（最も適切、難易度 3、狙う正答率 60%）

ランサムウェアの被害に備えて、社外の連絡先（警察、委託先、取引先、専門の事業者）の一覧を作った。保管の方法として最も適切なものはどれか。

1. 社内のファイルサーバだけに置き、全員が見られるようにする
2. 社内のファイルサーバに加え、社内ネットワークが止まっても見られる形でも保管する（正解）
3. 担当者の記憶に頼り、一覧は作らずにおく
4. 最新の状態を保つため、被害が起きた時に作り直す

選択肢ごとの解説：

1. ランサムウェアの被害では、複数のサーバやバックアップまで暗号化される場合が多い。社内ネットワークの中だけに置くと、必要な時に見られない。
2. 社内ネットワークが使えなくても参照できる形（印刷、別系統の保管）でも持つ。見直しの時期も決めておく。
3. 担当者が不在の時や、連絡先が変わった時に対応できない。
4. 被害の最中に作り直す余裕はない。平時に作り、定期的に更新する。

ポイント：社外の連絡先は、社内ネットワークが止まっても見られる形でも保管し、定期的に見直す。
出典：S3（BCP に連絡先を整理しておくこと、バックアップも暗号化される場合が多いこと）。

#### mg-itops（秘密情報とクラウドの設定）

**mg-itops-01**（最初の行動、難易度 3、狙う正答率 58%）

クラウドサービスの API キーを含むファイルを、誤って公開のリポジトリに登録してしまった。数分後に気づいた。最初に行うことはどれか。

1. リポジトリからファイルを削除し、履歴も消す
2. 数分しか公開していないので、様子を見る
3. リポジトリを非公開に変え、問題がないかを後で確かめる
4. その API キーを無効化して新しいキーを発行し、報告する（正解）

選択肢ごとの解説：

1. 削除しても、公開されていた間に他人が複製した可能性は消えない。鍵そのものを使えなくすることが先である。
2. 公開されていた時間が短くても、その間に複製されていないとは言えない。時間の長さで安全とは判断できない。
3. 非公開にしても、すでに複製された鍵は使えてしまう。
4. 漏れた鍵はすぐ無効化し、新しい鍵には必要最小限の権限だけを与える。利用記録で不審な使用がないかを確かめ、報告する。

ポイント：漏れた鍵は、消すより先に無効化し、新しい鍵を最小の権限で発行して報告する。
出典：N2（API キーやクラウドの認証情報の流出への対策）。

#### 季節のテーマ（既存カテゴリ）

**aw-mail-04**（最も適切、難易度 2、狙う正答率 72%）

長期休暇の間、業務用のノートパソコンを自宅に持ち帰り、一度も起動しなかった。休み明けに社内のネットワークへつなぐ前の対応として最も適切なものはどれか。

1. すぐにつなぎ、たまったメールから確認する
2. 会社の手順に沿って、OS とウイルス対策ソフトを更新し、検査する（正解）
3. 休暇中に使っていないので、そのままつないでよい
4. 休暇中に届いたメールを、添付も含めてまとめて開く

選択肢ごとの解説：

1. 休暇の間に更新が止まっていると、新しい攻撃を防げない状態でメールを開くことになる。
2. 休暇の間に出た更新を当ててから使う。持ち出した端末や媒体は、社内で使う前に検査する。
3. 使っていなくても、休暇中に出た修正は当たっていない。
4. 休暇明けは不審なメールがたまりやすい。まとめて開かず、1通ずつ差出人と内容を確かめる。

ポイント：長期休暇の明けは、更新と検査を済ませてから社内のネットワークへつなぐ。
出典：N8（長期休暇における情報セキュリティ対策）。

**aw-scam-04**（場面、難易度 2、狙う正答率 72%）

確定申告の時期に、税務署を名乗る SMS で「未納の税金がある。本日中に次のリンクから納付を」と届いた。どうするか。

1. 本日中と書かれているので、リンクから納付する
2. SMS に書かれた電話番号に電話して確かめる
3. リンクを開かず、必要なら国税庁の公式サイトで調べた窓口に確かめる（正解）
4. 金額が小さければ、リンクから納付しても問題ない

選択肢ごとの解説：

1. 急がせるのは、確かめる時間を与えないための手口である。
2. SMS に書かれた番号は、攻撃者の番号のおそれがある。
3. 国税庁は、国税庁をかたる不審な SMS とメールについて注意を呼びかけている。確かめる時は自分で調べた窓口を使う。
4. 金額の大小にかかわらず、入力したカード情報や口座情報が悪用される。

ポイント：税務署を名乗る SMS やメールのリンクは開かず、自分で調べた窓口で確かめる。
出典：N13。

### 4.3 出し方の企画

#### 4.3.1 毎月の定期テスト（年間の出題計画）

小問（`awareness_quiz`）を毎月1回、3〜5問で配る。
答え合わせは1問ごと（`feedback_mode = immediate`）にし、合格点は設けない（今の小問の既定どおり）。
各月の重点は、公的機関が毎年同じ時期に注意を呼びかけている手口と、会社の行事に合わせた。

| 月 | 重点のカテゴリ | 季節の理由 | 根拠 |
|---|---|---|---|
| 4月 | aw-report、aw-auth、mg-offboarding（管理者） | 入社と異動。新しいアカウントと、不要になった ID の削除 | S7a（新規受入れ時の教育、ID の削除） |
| 5月 | aw-mail（休み明け）、aw-malware | 大型連休の明け | N9 |
| 6月 | aw-data、aw-genai | 季節の手口は特になし。正答率の低い分類を補う月にする | なし |
| 7月 | aw-remote、aw-scam | 夏休みの前。持ち出しとサポート詐欺 | N10 |
| 8月 | aw-remote（SNS）、aw-mail | 夏休み中の偽情報と不審メール | N10 |
| 9月 | aw-bec、aw-phishing | 上期末。経理担当者を狙う書類確認のメール | S10 |
| 10月 | aw-mobile、aw-phishing | 季節の手口は特になし。新設カテゴリを入れる月にする | なし |
| 11月 | aw-scam、aw-bec | 銀行を名乗る電話で法人口座を狙う手口が、2025年は11月に再び急増した | S3 |
| 12月 | aw-bec、aw-remote | 年末年始の前。社長を名乗る詐欺メールの相談が、2025年12月16日から約3か月で106件寄せられた | N11、S14 |
| 1月 | aw-mail（休み明け）、aw-malware | 年末年始の明け | N11 |
| 2月 | 全カテゴリの総まとめ（10問） | サイバーセキュリティ月間（2月1日から3月18日） | N12 |
| 3月 | aw-scam（税）、aw-bec | 確定申告の時期と年度末の支払い | N13 |

aw-report は、どの月にも1問を必ず入れる。
選定書の第5章で、SCS 評価制度の★3の年1回の教育要求に対応するため、どの配信回でも含める運用を勧めているためである。

#### 4.3.2 訓練メールと連動した出題

- **開いた人、入力した人**：訓練の失敗者を自動で教育に入れる配信（`triggered_by = phishing_failure`、対象は `risk`）で、企画12の教材と確認テスト5問を出す。確認テストは aw-mail、aw-phishing、aw-report から出題する。
- **開かなかった人、報告した人**：訓練の後に、同じ種類の手口の小問を3問だけ出し、報告した人には報告を続けてほしいことを伝える。
- **出題の時機**：訓練の期間中に、訓練と同じ手口の小問を全員に出すと、訓練の測定が崩れる。訓練の終了後に出す。

#### 4.3.3 難易度の段階

設問の難易度は1から3の3段階で、配信ごとに出題する難易度の範囲を指定できる。
これを使い、1年目の上期は難易度1と2、下期は2と3、2年目以降は3を多めにする。
既存の小問の正答率の目標（60〜85%）を段階の判断に使い、90%を超える分類は次の段階へ上げる。

#### 4.3.4 部署別、役職別の出し分け

- **部署別**：経理、財務、購買には aw-bec を、工場には aw-factory を、開発と IT には mg-itops を多めに出す。
- **役職別**：役員には mg-executive、部門長には mg-incident と mg-offboarding を出す。
- **新入社員**：入社から1か月以内に企画11と確認テストを出す。

### 4.4 今の機能でできることと、追加が要ること

tet2 のコード（教育の配信の API と設問のスキーマ）で確かめた結果を分けて書く。

今の機能でできることは次のとおりである。

| 出し方 | 使う機能 |
|---|---|
| 小問と確認テストの区別 | 配信の種別（`elearning` と `awareness_quiz`） |
| カテゴリと問題数の指定、並びの無作為化 | 配信のカテゴリ（複数可）、問題数、難易度の範囲、無作為化 |
| 1問ごとの答え合わせ | `feedback_mode`（`immediate` と `after_submit`。小問の既定は `immediate`） |
| 確認テストの合格点80% | 合格点（`pass_score`）。合格の判定は e ラーニングの配信だけ |
| 選択肢ごとの解説、場面の画像 | 設問の `option_explanations` と `image_name` |
| 訓練で開いた人、入力した人への自動の出題 | `triggered_by = phishing_failure` と対象 `risk`。ただし自動投入の timer（`tet2-edu-enroll`）は利用者の方針で止めてあり、動かすには利用者の承認が要る |
| 部署別の出し分け | 対象の種類 `group` と、部署の種類のグループ（`groups.kind = department`） |
| 年間の出題計画 | 12回分の配信を作り、各月の当日に手で開始する（予約の日時 `scheduled_at` は保存できるが、自動で開始する処理はない） |

機能の追加が要ることは次のとおりである。

| 出し方 | 足りない点 | 関係する設計 |
|---|---|---|
| 予約した配信の自動の開始 | 予約の日時に配信を開始する処理がない | なし（新規） |
| 毎月の自動の配信 | 繰り返しの規則がなく、毎月の配信を手で作る必要がある | 07 設計書の U5（定期の小テスト） |
| 同じ人に同じ設問を出さない | 出題の選び方は、過去に解答した設問を除かない | なし（新規） |
| 役職別の出し分け | 対象者に役職区分（`position_category`）はあるが、配信の対象に指定できない。手作業のグループで代える必要がある | なし（新規） |
| 開かなかった人、報告した人への出題 | 自動の投入は失敗者（開いた、入力した）だけが対象である | なし（新規） |
| 新入社員への自動の出題 | 配信の起点に `new_target` の値はあるが、自動で投入する処理は `phishing_failure` だけである | なし（新規） |
| 個人の成績に合わせた難易度 | 難易度の範囲は配信ごとに一つで、人ごとに変えられない | なし（新規） |
| カテゴリの2階層化と分野別の理解度 | カテゴリは1階層で、設問は1カテゴリに属する | 07 設計書の U5 |
| 正答率の目標から外れた設問の発見 | 設問ごとの正答率の画面がない | 08 検討書の G22 |

新設カテゴリ6個の追加は、教材カテゴリの登録で足り、機能の追加は要らない。

## 5. 今回は企画しない題材

- **医療機関向けと小売向けの業種別の版**：tet2 の顧客の業種が決まった時に、企画18と同じ形で作る。根拠となる業種別のガイドラインは、今回は確かめていない。
- **ディープフェイクの単独の教材**：既存企画の3.4（ビジネスメール詐欺）と3.7（生成 AI）で扱っており、国内の公的な被害統計も確かめられていない。
- **標的型攻撃メールの見分け方の単独の教材**：既存企画の3.2と、企画12で扱う。

## 6. 制作の順序

既存企画の第4章の順序（3.2と3.4を次に作る）は変えない。
新しい企画は、既存の10本のうち完成済みの教材を使えるものから作る。

### 6.1 最初に作る3本

1. **企画11（入社の日に覚える5つの行動）**：SCS 評価制度の★3が新規受入れ時の教育を求めており[S7a]、顧客が教材を買う理由に直接つながる。既存企画の3.1（完成済み）と、今後できる3.2、3.5、3.6、3.7から場面を借りられるため、制作の費用が小さい。4月の入社に合わせるには、2027年2月までに完成させる必要がある。
2. **企画12（訓練のメールで、どこで気づけたか）**：tet2 の本番の訓練で、偽サイトを表示した人の58.4%が入力まで進んでいた[N14]。訓練から教育への自動連携はすでにあり、教材ができれば機能の追加なしに配信できる（timer の有効化は利用者の承認が要る）。3.2の後に作る。
3. **企画13（経営層が決めておくこと）**：SCS 評価制度の★4が経営層の教育を求め[S7a]、被害組織の BCP の策定は約18%にとどまる[S3]。経営層が教育の予算を決めるため、この教材は他の教材の採用にもつながる。既存企画の3.3（完成済み）の統計と場面を使える。

### 6.2 その後の順序

4. 企画18（工場）：顧客の現場の手順を聞き取れた時点で作る。
5. 企画14（机上演習）：既存企画の3.3の品質確認の後に作る。
6. 企画17（社外と出張）と企画16（スマートフォン）：季節の配信（長期休暇の前）に合わせて作る。
7. 企画15（秘密情報とクラウド）：IT 部門を持つ顧客から求められた時に作る。
8. 企画19（執務室）と企画20（SNS）：小問を先に作り、教材は短い版にとどめる。

## 8. 確かめられなかった点

- **経済産業省のサイト**：2026年9月27日に、経営ガイドラインのページ[S8]、工場のガイドラインのページ[N5]、SCS 評価制度の要求事項の Excel[S7a] のいずれも HTTP 403 を返した。
  - 経営ガイドラインの3原則と重要10項目は、IPA の掲載[N1]で照合した。Ver3.0 が最新版であることは再照合できていない（選定書の第7章と同じ）。
  - 工場のガイドラインは、IPA の報告書[N6]で2022年11月の公開を照合した。その後の改訂の有無と最新の版番号は照合できていない。
  - SCS 評価制度の★3の新規受入れ時の教育（4-2-2-1）と★4の経営層の教育（4-2-1-1）は、選定書の作成時に Excel から取得した内容で、今回は民間の解説記事で同じ内容を見たにとどまる。教材に項番と文言を書く前に、Excel で確かめる。
- **QR コードによるフィッシングの件数**：フィッシング対策協議会の緊急情報[N7]で手口は確かめたが、国内の件数の統計は確かめられなかった。フィッシングレポート 2026（2026年6月1日公表）の本文は読んでいない。
- **物理の場面と SNS の被害統計**：入館、来訪者、SNS の投稿に起因する被害の国内の公的な統計は見つからなかった（企画19と20の優先度を低にした理由）。
- **医療と小売の業種別のガイドライン**：今回は確かめていない（第5章）。
- **国税庁の注意喚起[N13]**：ページの更新日は確認できなかった。見本の設問（aw-scam-04）は、国税庁が同庁をかたる不審な SMS とメールに注意を呼びかけている、という範囲だけを根拠にした。
- **tet2 の本番の数値[N14]**：顧客1社の1回の訓練の値で、他の顧客や他の回に一般化できるかは確かめていない。教材に数値を載せる時は、tet2 の顧客の数値であることと、回数と対象者数を併記する。
- **tet2 の機能**：第4.4節はコードの読み取りで確かめ、画面での操作は確かめていない。教育の文書の README（第5章）は「設問に画像を付けられない」と書いているが、今のスキーマには画像と選択肢ごとの解説の列があり、README が古い可能性がある。
