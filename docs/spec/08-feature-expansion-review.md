# 08. 教育コンテンツの拡充に向けた機能拡張の検討

対象システム: TET v2（標的型メール訓練およびセキュリティ教育システム）
版: 2026-09-27 作成、同日に利用者が第7章の3点を確認した。
TET v2 はリポジトリ HEAD `189e707` の実装、セキュリオは 2026-09-24〜26 に閲覧した画面と、テスト用の受講者アカウントでの受講に基づく。
位置づけ: [07 実機調査にもとづくアップデート設計書](07-seculio-benchmark-update-design.md)（以下「07」）の差 G01〜G15 と設計 U1〜U9 を前提とし、07 が扱っていない教育機能の差を G16 以降として追加する。

## 1. 検討の目的

TET v2 では、画像付きの図解教材（A5 判の PDF と、情報量を絞った PowerPoint の2形式）と、場面の画像付きの小問を新たに制作する計画がある。
この計画を進めるうえで、現在の教育機能にはコンテンツを受講者へ届けられない箇所がある。
本書は、その箇所と、全件撮影と受講者側の確認で新たに分かったセキュリオとの差を洗い出し、優先度と実装順を示す。

07 がすでに設計した次の機能は、本書では再掲しない。

- **U5 分野別の理解度評価**：設問の2階層タグ、解答の所要時間、定期の小テスト（`awareness_quiz`）、分野別と部署別の理解度。
- **U7 アンケート**：実装済み（`d530b15`）。

## 2. 現在の教育機能の要点

本書の差の評価は、次のコードの事実に基づく。

- **教材**：`edu_materials.slides` に、スライドごとのタイトルと本文の文字列を JSON で持つ（1〜50件、`web/api/edu_materials.php:53`）。
  PowerPoint の取込も文字だけを読み、画像、動画、レイアウトを捨てる（`docs/education-material-bank.md:57`）。
  教材には版と対象者の属性がない。
- **設問**：`edu_questions` は選択肢（`options`）、正解、解説（`explanation`）を1つずつ持つ。
  解説は設問に1つで、選択肢ごとには持てない。
  画像の列はない。
- **配信**：`edu_deliveries` は教材を1つだけ指す（`material_id`）。
  受講期限（`deadline`）と合格点（`pass_score`）はある。
- **受講画面**：`web/take.php` は、教材を文字のスライドとして1枚ずつ表示し、確認テストを提出した後の結果画面で、設問ごとの正誤と解説をまとめて表示する（`take.php:230-271`）。
  受講者はメールのリンク（`edu_assignments.access_token`）から入る。

## 3. 追加の差

| ID | 領域 | セキュリオで確認した仕様 | TET v2 の現状（根拠） | 差の評価 | 優先度 |
|---|---|---|---|---|---|
| G16 | 教材の表示形式 | スライド教材をページ画像のビューアで表示し、動画の教材も持つ（34レッスン中、スライド24件、動画3件） | 文字のスライドだけを表示する（第2章） | 大。図解教材を作っても受講者に届かない | 高 |
| G17 | 設問の画像と選択肢ごとの解説 | 答え合わせで、正解と、選択肢ごとの解説を示す | 解説は設問に1つ。画像を持てない（第2章） | 大。場面の画像を使う小問と、誤答ごとの指導が作れない | 高 |
| G18 | 解答直後の答え合わせ | 小問は選択肢を押すと、その場で正誤と解説を示し、最後に振り返りを出す | 提出後の結果画面でまとめて示す（`take.php:230-271`） | 中。小問形式では、答えた直後の解説のほうが記憶に残る | 中 |
| G19 | 複数の教材の束 | カリキュラムに複数のレッスンを並べて配信し、順に受講させる | 配信は教材を1つだけ指す（`edu_deliveries.material_id`） | 中。年間の研修計画を1本の配信で表せない | 中 |
| G20 | 教材の版 | 題材名に年版を付けて改訂している | 教材に版がなく、編集すると受講中の配信の内容も変わる（`edu_materials`） | 中。受講済みの記録が、どの内容に対するものか分からなくなる | 中 |
| G21 | 対象者の区分 | 同じ題材を管理者向けと従業員向けに分け、ページ数と重点を変えている | 教材に対象者の属性がない（`edu_materials`） | 小。題名で区別すれば運用できる | 低 |
| G22 | 設問の品質分析 | 設問ごとの解答状況を一覧できるが、正答率や識別力の指標は見当たらない | 解答ごとの正誤（`edu_response_answers.is_correct`）はあるが、設問ごとの集計画面はない | 中。易しすぎる設問を見つけられない | 中 |
| G23 | 見分け演習の教材 | 模擬メールの画面を示して怪しい箇所を問い、次のページで答えを示す演習型の教材がある | 教材は文字だけ。訓練テンプレートを教材から参照する仕組みはない | 小。G16 が入れば画像ページで表現できる | 低 |

G22 の評価には、セキュリオの解答データの集計を根拠にした。
調査テナントの解答済み 1,420 件のうち 97.7% が正解で、5回以上解答された175問では正答率の四分位がすべて100%だった。
ほぼ全員が正解する設問は受講の記録にはなるが、追加の教育が必要な人を見分けられない。
TET v2 の小問は、正答率の目標を 60〜85% に置いて作る予定であり、目標から外れた設問を見つける画面が要る。
なお、解答結果の値のうちどちらが正解を表すかは画面から確かめておらず、件数の多い値を正解とみなしている。

## 4. 機能ごとの案

### 4.1 G16 教材の表示形式

教材に形式の区分を加え、既存の「文字のスライド」に「ページ画像」を足す。
ページ画像の教材は、PDF を取り込んでページごとの画像に変換して保存し、受講画面で1ページずつ表示する。
PowerPoint は、利用者の手元で PDF に書き出してから取り込む運用とし、サーバーで PowerPoint を画像にする処理（LibreOffice の導入が必要）は持たない。
画像を読めない受講者と検索のために、各ページの文字を PDF から抜き出して代替テキストとして保存する。

**データ**：`edu_materials` に形式（`format`：`text_slides` か `page_images`）と、ページ数を追加する。
ページ画像は Web から直接読めない場所に置き、受講者のトークンを確かめてから返す API を通して表示する。
既存の教材は `text_slides` として扱い、表示を変えない。

**検証**：PDF の取込でページ数と画像数が一致すること、他のテナントや期限切れのトークンで画像を取得できないこと、既存の文字の教材の受講が変わらないことを確かめる。

### 4.2 G17 設問の画像と選択肢ごとの解説

`edu_questions` に画像（任意）と、選択肢ごとの解説（`option_explanations`、選択肢と同じ順の配列）を追加する。
設問全体の解説（`explanation`）は残し、選択肢ごとの解説がない設問では従来どおりそれを表示する。
Excel の取込列に、選択肢ごとの解説と画像ファイル名の列を追加する。
画像は Excel とは別に ZIP でまとめて取り込む。

### 4.3 G18 解答直後の答え合わせ

配信に答え合わせの時機（`feedback_mode`：`after_submit` か `immediate`）を持たせる。
`immediate` の配信では、受講者が1問答えるごとに正誤と解説を表示し、最後に全問の振り返りを表示する。
07 の U5 で設計した定期の小テスト（`awareness_quiz`）の既定値を `immediate` とし、確認テストの既定値は従来どおり `after_submit` とする。
1問ごとに解答を保存するので、途中で中断した受講者も続きから再開できる。

### 4.4 G19 複数の教材の束

新しいテーブル `edu_courses`（テナント、名称、説明）と `edu_course_items`（コース、教材、順序、確認テストの有無）を追加し、配信がコースを指せるようにする。
配信が教材を1つだけ指す既存の形は残す。
受講画面は、コースの教材を順に表示し、各教材の終わりに確認テストを挟む。

### 4.5 G20 教材の版

教材を編集したときに版を上げ、配信した時点の版を固定する。
`edu_material_versions`（教材、版、内容、作成日時）を追加し、配信は教材の版を指す。
受講済みの記録は、受講した版とあわせて表示する。
年版の改訂は新しい版として作り、次回の配信から使う。

### 4.6 G21 対象者の区分

教材に対象者（`audience`：`employee`、`manager`、`all`）を追加し、教材バンクの一覧で絞り込めるようにする。
テナント共有の教材（`is_shared`）を管理者向けと従業員向けの対で用意する運用に使う。

### 4.7 G22 設問の品質分析

教育の画面に、設問ごとの解答数、正答率、選択肢ごとの選択率、所要時間（07 の U5 で追加する `answer_ms`）の一覧を加える。
正答率が 90% を超える設問と 40% を下回る設問に印を付け、選択肢の見直しを促す。
識別力（全体の成績が上位の受講者と下位の受講者の正答率の差）は、解答数が十分に集まった設問に限って表示する。

### 4.8 G23 見分け演習の教材

G16 のページ画像の教材として、模擬メールの画面と解答のページを2枚1組で作れば、新しい機能なしで表現できる。
訓練テンプレートから模擬メールの画像を作る機能は、G16 の運用を見てから判断する。

## 5. 推奨する実装順

推奨は、G16 と G17 を先に入れ、制作中の図解教材と小問を受講者に届けられる状態を作る順序である。
コンテンツの制作と並行して進められ、公開の時期をコンテンツの完成に合わせられる。

| 順 | 差 | 理由 | 07 の段階との関係 |
|---|---|---|---|
| 1 | G16 | 図解教材を受講者に届ける前提になる | 07 の段階 B と並行して新たに設ける |
| 2 | G17 | 画像付きの小問と選択肢ごとの解説の前提になる | 同上 |
| 3 | G22 | 小問の品質を運用で直すために要る。U5 の画面に同居させると工数が小さい | 段階 C の U5 に含める |
| 4 | G18 | U5 の定期の小テストと同時に入れると、受講画面の改修が1回で済む | 段階 C の U5 に含める |
| 5 | G20 | G16 の後に教材の改訂が始まる前に入れる | 段階 C の後 |
| 6 | G19 | 年間の研修計画の運用が始まる時点で入れる | 段階 C の後 |
| 7 | G21、G23 | 運用で代替できる | 需要を見て判断 |

各段階の完了条件と検証は 07 第7章と同じとし、`bash web/tests/run.sh` と Python のテストを通し、認証済みの実 HTTP で受講画面を確かめる。
データの変更は列とテーブルの追加だけで構成し、既存の列の意味を変えない。

## 6. 取り入れない機能

- **漫画の教材**：作画と校正の工程を品質を保って持てないため。
  図解教材の案内役の吹き出しで、会話の要素を補う。
- **受講者のポータル（ログインして配信一覧を見る画面）**：受講者の認証を新たに持つ必要があり、07 第8章で見送った外部 IdP 連携の判断と結び付く。
  メールのリンクから受講する現在の形を続ける。
- **サーバーでの PowerPoint の画像化**：LibreOffice をサーバーに入れる運用の負担に比べ、PDF に書き出してから取り込む運用で足りるため。

## 7. 利用者の確認結果

2026-09-27 に、利用者が次の3点を確認した。

1. G16 と G17 を、07 の段階 B と並行する新しい段階として先に進める。
2. G16 では、PowerPoint は PDF に書き出してから取り込む運用とする。
3. G22 の正答率の印の基準は、90% 超と 40% 未満とする。
