# 05. 利用マニュアル

対象システム: TET v2（標的型メール訓練およびセキュリティ教育システム）
版: 2026-09-24 時点の実装（リポジトリ HEAD `9aafa33`）に基づく。
位置づけ: 本書は管理者の画面操作と、受講者の操作を説明する。配備や障害対応は運用手順書を参照する。

本書の画面名とタブ名は、実装（`index.html`、`app.js`、`take.php`）の表示に合わせている。

## 1. 管理画面へのログイン

ブラウザで管理画面を開き、メールアドレスとパスワードでログインする。
ログインに繰り返し失敗すると、アカウントは一時的にロックされる。時間をおくか、管理者に解除を依頼する。
役割によって使える操作が変わる。閲覧だけの利用者（viewer）は変更操作ができない。

## 2. 画面の全体

管理画面は次の画面で構成される。

- ダッシュボード
- キャンペーン
- テンプレート
- 偽ログインページ（masters）
- ログ管理
- グループ
- 役職
- レポート
- ユーザ
- テナント

教材、教育配信、不審メール、リスクは、これらの画面やレポートのサブメニュー、タブから利用する。

## 3. ダッシュボード

ログインすると最初に表示される。訓練の状況の概観を示す。本番とテストの区別で表示を絞り込める。

## 4. 対象者とグループ、役職

### 4.1 対象者

「受講者・訓練対象者」のタブで、訓練の宛先であり教育の受講者でもある対象者を管理する。
新規登録、編集、削除、一覧のほか、CSV による一括取込と書き出しができる。削除した対象者は復元できる。効果測定に含めないテスト用の対象者は、フラグで区別する。

### 4.2 グループ

対象者をまとめて訓練の対象に指定する単位である。作成、編集、削除と、メンバーの追加や削除を行う。

### 4.3 役職

会社と役職の組み合わせをマスタとして管理し、対象者へ一括で適用する。会社別、役職別の集計と、設定の網羅状況を確認できる。

## 5. テンプレートと偽ログインページ

「テンプレート」で、件名、本文、偽ログインページ、種明かしページ、eラーニングの文面を管理する。共有の雛形と、自組織のものがある。作成、編集、削除、シナリオ単位の作成、CSV の取込と書き出しを行う。
「偽ログインページ」（masters）では、偽ログインページ用の HTML を確認し、アップロードする。

## 6. キャンペーン

キャンペーンは訓練の実施単位である。

### 6.1 下書きの作成と編集

新規作成すると、下書きの状態になる。編集は次の6手順で進む。

1. 基本情報
2. 対象者
3. シナリオ
4. 日時と送信量
5. 送信環境
6. 最終確認

「すべて表示」で一覧編集に切り替えられる。どちらも同じ下書きを保存する。保存しただけでは配信されない。
複製、名称変更、取消も行える。編集画面は多数のコンテンツに対応し、過去のキャンペーンからの一括取込、折りたたみ、並べ替えを使える。

### 6.2 配信前確認

下書きの「配信前確認」で、対象人数、総通数、テスト転送先ごとの通数、開始できない理由を確認する。
確認の後に設定、対象者、テンプレートが変わると、開始操作は拒否され、再確認を求められる。

### 6.3 起動と停止

配信前確認を通ると、起動できる。起動すると、送信用のデータと偽ログインページ、リンク、添付を生成し、全行の検証に成功したときにだけ配信を始める。
配信中は停止と再開ができる。停止したものは下書きへ戻せる。進捗は画面で確認する。

### 6.4 テストキャンペーン

テストキャンペーンは、全送信行を指定したテスト宛先へ均等に転送する。テスト宛先が空のときは生成と配信を拒否し、本番宛先へは送らない。送信後でも、本番とテストの区別を切り替えられる。

### 6.5 定期キャンペーン

「定期キャンペーン」で、月次や四半期の規則からレビュー用の下書きを自動生成する。元のキャンペーン、対象グループ、実施日、時刻を設定する。生成されるのは下書きであり、配信には手動の起動が必要である。完了済みの均等割りキャンペーンをコンテンツの供給元に選ぶと、従業員ごとに前回と別のコンテンツを割り当てられる。

## 7. レポート

「レポート」で、訓練の反応を集計する。サマリー、明細、キャンペーン別、偽サイトのビーコン別、個人別を確認できる。
Excel へ書き出すと、サマリー、会社別、役職別、コンテンツ別、日別、訓練結果、訓練結果ログ、返信者のシートが得られる。
集計は確定と解除ができ、統計を確定した後にキャンペーンをクローズできる。

集計の語彙に注意する。偽サイトのビーコンは、メールの開封ではなく偽サイト側の反応である。古い資料の「開封率」をそのまま報告に転載しない。

## 8. リスク

レポートのリスク関連の画面で、会社別と個人別のリスク、再訓練の推奨を確認する。
リスクは、観測した行動（未開封、開封、クリック、入力、返信）を重み付けし、直近の行動を重く見て評価する。再訓練の推奨者と、推奨する教育カテゴリを示す。

## 9. ログ管理

「ログ管理」で、次のタブを切り替えて確認する。各タブは CSV と Excel へ書き出せる。

- 送信ログ
- 訓練イベント
- スケジュール
- 訓練結果 / 訓練結果ログ（明細）
- 入力本文（管理者限定）
- リンク / ビーコンファイル
- 報告メール
- 操作ログ
- 生メールログ / 生 Web ログ / Web アクセスログ
- 返信者

「入力本文（管理者限定）」は、承認制で収集した入力値を、システム管理者だけが復号して確認するタブである。復号は監査を伴う。
「報告メール」は、従業員が報告した疑似フィッシングのメールを一覧し、対象のキャンペーンとの照合を確定または却下する。
「返信者」は、実際に受信したメール（Maildir）を表示する。
Web アクセスログの地域推定は、負荷を避けるためキャッシュ表示と明示更新に分かれている。

## 10. 教材と教育

### 10.1 教材

教材のカテゴリを作成、編集、削除、複製する。教材は PowerPoint（`.pptx`）からスライドのタイトルと本文を取り込み、保存前に編集できる。

### 10.2 設問

確認テストの設問を管理する。Excel（`.xlsx`）のテンプレートをダウンロードして一括で追加でき、自組織と共有の全設問を Excel へ書き出せる。全カテゴリの一覧、1問ずつの試行、正答と解説を含む全設問の一覧を確認できる。

### 10.3 教育配信

教育配信を作成、編集、削除し、起動と催促を行う。
教育の割当と催促を自動で行う処理は用意されているが、実在の従業員へメールを送るため、既定では停止している。有効化は運用手順書に従う。

## 10a. アンケート

「アンケート」（教育の区分）で、訓練や教育の後に配るアンケートを作成、配信し、結果を集計する。

作成は「雛形から作成」（訓練後の振り返り、教育後の理解確認）か「新規作成」で行う。
設問の形式は単一選択、複数選択、自由記述の3つで、必須の指定と、前の設問の選択肢による表示条件を設定できる。
匿名にすると、回答と回答者を結び付けずに保存し、回答者別の出力を行わない。

「配信」でグループを選ぶと、対象者を確定し、回答用のリンクを発行する。
配信を作った後は設問を編集できない。
変更する場合は複製して、新しいアンケートとして配る。

メール送信は既定で無効である。
配信一覧の「回答用 URL（CSV）」で未回答者の回答用リンクを出力し、社内のメールで配布する。
送信を有効にした環境では、「案内メール」と「催促」（締切の2日前から1人1回）を使える。

「結果」で回答率、部署ごとの回答率、設問ごとの回答の分布、自由記述を確認し、Excel と CSV へ出力する。
テスト用の対象者は、母数と回答の両方から除く。

## 11. 不審メール

従業員から寄せられた不審メールを `.eml` 形式でアップロードし、オフラインで解析する。一覧と取得、再解析、レピュテーションの照会を行う。

## 12. ユーザとテナントの管理

「ユーザ」（管理画面ユーザ）で、管理アカウントを作成、編集、削除する。役割で操作範囲が変わる。
「テナント」は、全テナントを扱う管理者が、顧客組織を作成し、名称や識別子、状態を管理する画面である。

## 13. 受講者の操作

受講者は、受講者ポータル（専用のサブドメイン）で、メールに含まれるトークンから受講を開始する。
アンケートも同じく、案内された回答用のリンクから開き、回答して送信する。
回答は1回だけで、締切を過ぎると回答できない。
教材を確認し、確認テスト（クイズ）に回答して提出する。合格すると完了になる。管理系の画面には入れない。

## 14. 検証報告

- 画面名: `index.html` の `data-view`（dashboard / campaigns / templates / masters / logs / groups / positions / reports / users / tenants）と、ログ管理のタブ名、対象者タブ名を実表示から採った。証拠は `web/index.html`。
- 機能の導線: 教材、教育、不審メール、リスクが実装のラベル（教材、教育、不審メール、リスク）として存在することを確認した。
- 受講者操作: `take.php` の受講とクイズ、回答の表示を確認した。
- 未確認: 認証済みの実際の画面遷移と、役割ごとの表示の出し分けは、静的な確認にとどめ、実操作では確かめていない。
- 一番弱い箇所: 教材、教育、不審メール、リスクの画面が、メニューのどの階層から開くかは、実装のラベルの存在までは確認したが、正確なクリック経路は実操作で確かめていない。画面名は正しいが、たどり方は実機で最終確認する必要がある。
