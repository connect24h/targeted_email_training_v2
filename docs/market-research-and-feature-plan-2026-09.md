# TET v2 市場調査と新機能開発計画（2026-09-05）

本書は、標的型メール訓練・Eラーニング・セキュリティアウェアネス市場の調査結果と、TET v2 の現状を突き合わせ、
次に開発する機能を優先順位付きで定めた計画である。実装は含まない。調査の一次資料は
`docs/research-2026-09/` 配下の `research-global.md`（海外大手）/ `research-japan.md`（国内競合）/ `research-market.md`（市場規模・規制・研究）で、
本書の数値・事実は全てそのいずれかか TET v2 のコードに由来する。出典 URL は各調査ファイル末尾にある。

## 1. 結論

- 市場の評価軸は「開封率・クリック率」から「報告率」と「その場での短い介入」へ移っており、
  TET v2 は報告イベントの取込経路だけが未実装で、それ以外（報告率の描画、リスクスコアの減点）は既に動く状態にある。
  **最初に着手すべきは報告動線の実装**で、投資が最小で差別化と測定精度の両方に効く。
- 海外大手は SMS・音声・QR・Teams・ディープフェイクへ経路を広げ、AI でシナリオを生成し、1人あたり年 15〜30 ドル前後で提供している。
  国内はセルフ型が 1人あたり月 50〜320 円、運用代行型が 1回 21〜88 万円で、老舗（NTT東日本）の撤退と AI 系新興（AironWorks、サギトレ）の参入が同時に起きている。
- TET v2 の勝ち筋は価格ではなく「日本語の実運用同等シナリオ + 運用代行 + 経営層に説明できる報告率・リスク指標 + ガイドライン証跡」の組み合わせである。
- 計画は 5 フェーズ（0〜4）、合計およそ 22 週の一人運用 + AI 委譲を想定する。各フェーズは単独で価値が出る順に並べ、前のフェーズの計測結果で次を見直す。

## 2. 前提（ヒアリング結果）

| 項目 | 決定 |
|---|---|
| 提供形態 | 自社サービスとして顧客企業へ提供（現行のゴールドウイン型・運用代行） |
| 調査範囲 | 国内主要 + 海外大手 |
| 優先軸 | 受注・差別化 / 運用工数の削減 / 訓練の測定精度 / 教育の充実（4軸すべて） |
| 運用体制 | 作業者一人。四眼承認は保留（既存判断を維持） |
| 制約 | 訓練メール本文へ訓練と見破る手掛かりを混ぜない（測定目的を壊す）。実在従業員への送信を伴う自動化は明示指示なしに有効化しない |

## 3. TET v2 の現状

### 3.1 実装済み

| 領域 | 内容 |
|---|---|
| 基盤 | マルチテナント（4層の分離）、ロール 4 段階、CSRF、レート制限、OWASP Top 10 診断済み、実 HTTP 検証済み |
| 訓練の攻撃経路 | メール本文リンク、QR コード、添付ファイル、偽ログイン画面 5 種（`auth_flag`、MS365 メールのみ型を含む）、返信型（Maildir 実受信の表示） |
| キャンペーン運用 | 全コンテンツ配信、事前生成による失敗検出、draft 戻し・複製・論理削除、営業時間内送信、緊急停止、テスト対象者の除外、bot クリック除外 |
| 自動化 | 定期 rule から draft を自動生成（`campaign_automations`）。自動送信はしない。個別 rotation と大量コンテンツ編集も配備済み（2026-09-05 確認） |
| 計測・レポート | 開封・クリック・認証・報告率（描画のみ）、認証率 2 定義、期間指定、8 シート Excel、会社別・役職別・コンテンツ別・日別、GeoIP、返信者 |
| リスクスコア | `HumanRiskScore`（開封 1・クリック 8・認証 20、報告 6 で減点、時間減衰、教育の未受講・不合格で加点）。日次計算、`risk-dashboard.js` で表示 |
| 教育 | 12 カテゴリ 100 問、スライド型教材、合否制 e-learning と継続型クイズ、token 方式の受講ポータル、訓練失敗者の自動割当（timer は停止中）、催促、スコア snapshot |
| 対象者管理 | CSV 取込、役職マスタ → 役職カテゴリ、論理削除、テスト用フラグ |

### 3.2 未実装（本計画の対象候補）

- 報告イベントの取込経路（`EventIngest.php` に「未実装」と明記。入れば報告率・リスク減点が動く）
- メール以外の攻撃経路（SMS、音声、Teams/Slack、ディープフェイク）
- 偽操作手順型（ClickFix）、MFA コード窃取型の偽ログイン
- AI によるシナリオ生成（現状は 46 件の手書きテンプレートと preset）
- 経営層向けの整形済み報告書（PDF/PPTX）とガイドライン対応の証跡出力
- 修了証、受講記録の監査用エクスポート、SCORM
- 顧客が自分で閲覧する専用ポータル（管理 UI は sat ドメインで遮断）
- SSO/MFA、四眼承認（既存判断で保留）

## 4. 市場調査サマリ

### 4.1 市場規模と規制（`research-market.md`）

- 世界市場は定義により USD 0.2〜1.45B（2025）で CAGR 5〜16%。日本の標的型メール訓練市場の金額は ITR 会員限定で未確認。
- 訓練・教育を要求する制度: 経産省サイバーセキュリティ経営ガイドライン Ver3.0（継続教育の予算確保）、ISO/IEC 27001:2022 管理策 6.3（受講記録が監査対象）、金融庁ガイドライン（2024-10）、厚労省 医療情報 6.0 版、総務省 自治体ガイドライン（LGWAN 三層分離）、EU NIS2（訓練の法的義務）。経産省のサプライチェーン格付け（2026 年度後半開始予定）は教育要件が未確定。
- IPA 10 大脅威 2026 の組織編 3 位に「AI を悪用するサイバーリスク」が初選出。

### 4.2 海外大手の到達点（`research-global.md`）

| 観点 | 到達点 |
|---|---|
| 攻撃経路 | KnowBe4・Hoxhunt・Cofense がメールに加え SMS・音声・Teams/Slack に対応。Microsoft Defender は QR を標準化。KnowBe4 は幹部を模したディープフェイク動画を生成 |
| AI | 実攻撃メールを教材化（Proofpoint ThreatFlip）、個人ごとの適応難易度（Hoxhunt）、エージェント群（KnowBe4 AIDA 12 本、Proofpoint Satori） |
| 報告動線 | 報告ボタン + 通報の自動トリアージ（PhishER、Cofense Triage）が前提。報告率が主要 KPI |
| リスク管理 | Human Risk Score の数値化（Mimecast は 0-10 へ刷新）、Gartner は SACBT から Human Risk Management へ概念拡張 |
| 教育 | 数百コンテンツ、SCORM 出力（SoSafe）、Teams/Slack 上でのナッジ配信、ゲーミフィケーション、修了証 |
| 価格 | 1人あたり年 15〜30 ドル前後（第三者推計含む）。KnowBe4 は月 1.30〜2.35 ドル。Microsoft は E5 同梱 |

### 4.3 国内競合と価格帯（`research-japan.md`）

| 区分 | 代表 | 価格 | 特徴 |
|---|---|---|---|
| セルフ型 SaaS | LRM セキュリオ、MudFix、ラック T3 with 教育、KIS MailMon | 月 50〜320 円/人、年 36,000 円〜 | 回数無制限、Outlook/Gmail 報告アドイン（セキュリオ）、教材 90 種以上 |
| 運用代行型 | GSX トラップメール、ラック T3、日立、IIJ、NTT西日本 | 1 回 21〜88 万円 | コンサル助言、部署・役職別カスタム、GSX は導入 11,000 社超 |
| AI 系新興 | SB C&S AironWorks（2025-01）、トビラ サギトレ（2025-10） | 要問合せ | ニュース連動のシナリオ自動生成、SMS 訓練、部門別リスク傾向 |

### 4.4 訓練効果の研究知見と KPI の潮流（`research-market.md`）

- 2025 年の UCSD 等の大規模研究（19,500 人・8 か月）で、年次訓練とクリック者だけへの埋め込み型訓練は失敗率を有意に下げなかった。
- 一方、クリック直後にその場で教える介入は後続の被クリック率を平均 40% 下げ、インタラクティブ訓練を受けた群は報告頻度が 37% 高かった。
- 評価はクリック率単独から「報告率・報告までの時間・行動変容」の複合指標へ移行している。国内ベンダーも「開封率が低ければ合格」からの転換を提唱。

## 7. 開発計画

### フェーズ 0: 土台の確定（2 週）

- 未コミットだったリスクダッシュボード機能をコミットして本番へ配備する（rotation・大量コンテンツ編集は 2026-09-05 時点で配備済みと確認）。
- `/root/tet2` の未コミット差分（cache-bust、report、app.js）を確定し、Git 正本と本番の一致を再確認する。
- KPI を定義して基準値を記録する: 失敗率（クリック÷対象）、認証率（認証÷対象）、報告率（報告÷対象）、報告までの中央値時間、リスクバンド分布、教育完了率。ゴールドウインの既存 3 回分で基準値を出す。
- 完了条件: 配備後の実 HTTP smoke test 成功、KPI 基準値の表が `docs/` に残る。

### フェーズ 1: 報告率を測る（4 週）— 候補 A, C

- 報告用メールアドレス（テナント別）を用意し、対象者が訓練メールを転送・報告した時刻を `ReplyMaildir` の経路で `events.report` に取り込む。tracking_id を本文・ヘッダから復元し、bot 除外を通す。
- Outlook/Gmail アドインは作らない。転送方式なら顧客側の配布作業がなく、運用代行型と相性が良い。アドインは顧客要望が出た時に再検討する。
- レポートに報告率・報告までの時間・「クリックしたが報告した人」を追加する。リスクスコアの減点は既存実装が動く。
- 再訓練推奨ビュー: リスクバンド high と直近の失敗行動から「次に誰へ何を」を一覧化し、教育カテゴリを提案する。
- 月次レポートの自動配信: 期間指定 Excel を月初にテナント担当者へメール送付する timer（送信先は顧客の管理者のみ。対象者へは送らない）。
- 完了条件: テストテナントで転送 → `events.report` → 報告率 → リスク減点まで自動で通る。既存テスト全通過。
- 検証: 実 HTTP、Maildir 投函の E2E、bot 除外の回帰、IDOR テスト。

### フェーズ 2: その場で教える（4 週）— 候補 B, G

- 種明かしページ（`debrief` テンプレート）に 3 問の確認クイズと「なぜ見抜けるか」の要点を組み込み、閲覧・回答を `events` に記録する。訓練メール本文は改変しない。
- 全員向けマイクロ配信: 訓練失敗者だけでなく対象者全員へ月 1 回、30 秒で終わる 1〜2 問を配る配信タイプを `edu_deliveries` に追加する。実在従業員への配信は顧客とユーザーの合意後に有効化する。
- 修了証 PDF（`SimpleXlsx` と同様の自前生成か、HTML → PDF）と受講記録 CSV（誰が・いつ・何点・合否）を出力する。
- 完了条件: 種明かしクイズの回答率が Excel と Web に出る。修了証と受講記録が ISO 27001 6.3 の監査証跡として提示できる形になる。

### フェーズ 3: 攻撃手法の追随（6 週）— 候補 F, D, I, J

- MFA コード窃取型の偽ログイン（パスワード後にワンタイムコードを求める画面。入力値は保存しない）と ClickFix 型（偽の操作手順ページで「コピーして実行」を押した事実だけを記録）を追加する。
- AI シナリオ生成: Codex 委譲で「業界・時期・部署」からメール件名・本文・偽サイトの組を draft 生成し、テンプレートとして保存する。ガードレールは、実在人物の PII 不使用、給与・解雇・健康などの禁止テーマ、訓練の手掛かりを混ぜない、必ず人が承認してから launch する、生成ログを audit に残す、の 5 点。
- 教材拡充: AI 下書き + レビューでカテゴリ別に +50 問、宅配便・国税・偽ヘルプデスクなど日本固有シナリオを含める。
- SMS 訓練 PoC: 送信事業者、費用、特定電子メール法と SMS 送信元表示の扱い、従業員の同意取得方法を調べてから、テスト用番号だけで送受信と URL 追跡を試す。本番投入は PoC 結果を見て判断する。
- 完了条件: 新テンプレート種別が CSV/API/UI/deploy allowlist まで追従（`b405c9a` と同じ範囲）。AI 生成物のレビュー記録が残る。

### フェーズ 4: 売れる形にする（6 週）— 候補 E, H, K

- 経営層向け報告書 PDF: サマリー、部署・役職別、前回比、報告率、リスク分布、推奨アクション、ガイドライン対応表（経産省 Ver3.0 付録、ISO 27001 6.3、必要なら金融庁・厚労省）を 10 ページ以内で自動生成する。
- 顧客閲覧ポータル: viewer ロールをテナント固定で使い、レポート閲覧と Excel/PDF ダウンロードだけを公開する。管理 UI と別ホストにし、OWASP 診断と実 HTTP 検証をリリース条件にする。
- 運用ヘルス画面と Slack 通知: worker、timer、WAL、disk、失敗バッチ、Cloudflare 521。
- 完了条件: 報告書 PDF を顧客に納品できる。ポータルの `/e2e` と `/security-audit` を通す。

### 後回しにするもの

## 9. リスクと未確認事項

- **効果の証明**: 研究は「訓練は効かない」と読める結果も含む。報告率と初動時間を主指標にし、フェーズ 0 の基準値と比較して顧客へ説明する。

- **AI 生成の倫理**: 国内に明確な倫理ガイドラインは確認できなかった。禁止テーマと人の承認をガードレールとする。
- **顧客ポータルの露出**: 管理 UI を一部でも外部公開するため、IDOR・セッション・レート制限の再診断が必須。
- **価格の妥当性**: 日本の訓練市場の金額（ITR）と中小企業の予算中央値は未確認。価格設計は国内の価格帯マップを参考にし、本計画では決めない。
- **教育 timer の停止方針**: `tet2-edu-enroll` と `tet2-edu-reminder` は停止中。フェーズ 2 の配信を有効化する際はユーザーの明示指示を得る。
